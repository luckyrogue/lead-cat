# i18n (ru/en/kk) Implementation Plan (Phase 4b)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Both apps render in the user's chosen language (ru / en / kk), driven by the `language` preference shipped in Phase 4a. Stand up a lightweight i18n runtime in each app and translate the user-facing strings.

**Architecture:** A tiny custom i18n (no library): a `Locale` type, three dictionaries (`en`, `ru`, `kk`) of dot-path keys → strings, a pure `translate(locale, key, params)` with fallback chain **active-locale → en → key** and `{param}` interpolation, a `LocaleProvider` that resolves the active locale from the user's stored `language` (mini-app: settings query; admin: `/me`) with a default, and a `useT()` hook returning a bound `t(key, params)`. `en` holds the current English copy (source of truth); `ru`/`kk` are translations; any missing key degrades to English, never to a raw key. Components replace hardcoded strings with `t("namespace.key")`.

**Default locale:** unset `language` resolves to **`ru`** (the product's primary market — the Telegram bot already speaks Russian). Users can pick `en`/`kk` explicitly (the Phase 4a settings picker already saves `language`). English remains the source dictionary, so an unset user sees Russian where translated and English elsewhere.

**Tech Stack:** TypeScript, React (mini-app + admin, React Router v7), TanStack Query (the language value already flows via settings/`/me`).

**Scope:** i18n runtime in both apps + translation of the user-facing surfaces (shell/nav, auth/states, meetings, members/invites, profile/settings, checker, colleague). Backend already stores/serves `language` (Phase 4a) — no backend change. The Telegram bot's server-side Russian copy is out of scope (already Russian).

**Prerequisite:** Branch `feat/mini-app-meeting-parity`, on top of Phase 4a (HEAD `10290a6`, pushed to origin/main). Stage explicit paths only; never `git add -A`; never `.gitignore`. Commit trailer `Co-Authored-By: Claude Opus 4.8 <noreply@anthropic.com>`. Gate per app = `pnpm typecheck && pnpm lint && pnpm build`. IGNORE IDE diagnostics (stale LSP) — trust `pnpm` output.

**Translation guidance for implementers:** `en` = the existing English copy verbatim. `ru` = natural Russian (informal "ты"/playful tone matching the existing bot copy like "🐾"). `kk` = natural Kazakh. Keep placeholders (`{count}`, names) intact. Keys are dot-path, grouped by feature namespace (e.g. `meetings.title`, `common.save`, `nav.profile`). When unsure of a term, prefer a clear, common translation; the user can refine later.

```typescript
import type { Dict } from "~/shared/i18n/types"

function lookup(dict: Dict, key: string): string | undefined {
  const value = key.split(".").reduce<unknown>((acc, part) => {
    if (acc && typeof acc === "object" && part in (acc as Dict)) {
      return (acc as Dict)[part]
    }
    return undefined
  }, dict)
  return typeof value === "string" ? value : undefined
}

function interpolate(text: string, params?: Record<string, string | number>): string {
  if (!params) {
    return text
  }
  return text.replace(/\{(\w+)\}/g, (_, k) =>
    params[k] !== undefined ? String(params[k]) : `{${k}}`
  )
}

export function translate(
  active: Dict,
  fallback: Dict,
  key: string,
  params?: Record<string, string | number>
): string {
  const value = lookup(active, key) ?? lookup(fallback, key) ?? key
  return interpolate(value, params)
}
```

- [ ] **Step 4: context + hook** `app/shared/i18n/context.tsx`:
```typescript
import { createContext, useContext, useMemo } from "react"

import { dictionaries } from "~/shared/i18n/dictionaries"
import { translate } from "~/shared/i18n/translate"
import { DEFAULT_LOCALE, type Locale } from "~/shared/i18n/types"

type TFn = (key: string, params?: Record<string, string | number>) => string
const LocaleContext = createContext<{ locale: Locale; t: TFn }>({
  locale: DEFAULT_LOCALE,
  t: (key) => key,
})

export function LocaleProvider({
  locale,
  children,
}: {
  locale: Locale
  children: React.ReactNode
}) {
  const value = useMemo(() => {
    const active = dictionaries[locale] ?? dictionaries[DEFAULT_LOCALE]
    const t: TFn = (key, params) => translate(active, dictionaries.en, key, params)
    return { locale, t }
  }, [locale])
  return <LocaleContext.Provider value={value}>{children}</LocaleContext.Provider>
}

export function useT(): TFn {
  return useContext(LocaleContext).t
}

export function useLocale(): Locale {
  return useContext(LocaleContext).locale
}
```

## Notes & decisions

- **Custom lightweight i18n, no library** — matches the mini-app's "stay lightweight (no heavy deps)" rule and is trivially tree-shakeable. The pure `translate` is unit-tested.
- **Fallback chain active → en → key** means partial translations degrade to English, never to raw keys — safe to ship incrementally.
- **Default locale = `ru`** (primary market). Changeable in one constant (`DEFAULT_LOCALE`) + `resolveLocale`.
- **`language` already flows** from Phase 4a (mini-app settings query; admin `/me`); the picker already saves it. This phase makes it actually switch the UI.
- **Endonyms** for the language picker options ("Русский"/"English"/"Қазақша") stay literal.
- **Bot server-side copy** (Telegram messages) is already Russian and out of scope.
- **Coverage is best-effort per feature**; anything missed renders in English and can be filled later — call out remaining gaps in Task 9.
